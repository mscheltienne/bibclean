Configuration🔗

bibclean runs without any configuration. Every option below changes either the canonical style or the rules, and lives in a TOML table.

Discovery🔗

For each input file, bibclean walks up from the directory of that file to the root of the filesystem and stops at the first directory holding one of:

  1. .bibclean.toml

  2. bibclean.toml

  3. pyproject.toml containing a [tool.bibclean] table

A dedicated file wins over pyproject.toml in the same directory, and two files in different projects each use their own configuration.

In pyproject.toml the keys live under [tool.bibclean]. A dedicated file, like any file passed to --config other than a pyproject.toml, writes them at the top level, and its per-type tables are top-level tables such as [article].

# bibclean.toml
indent = 4
exclude = ["ignored_entry"]

[article]
required = ["author", "title", "year"]

-c, --config FILE replaces the discovered file for every input, and --isolated ignores every file and runs with the defaults. The two are mutually exclusive. --ignore adds rule names to whichever configuration applies, including the defaults.

An unknown key, a value of the wrong type and an unknown rule name in ignore are errors, reported with the name of the key and a suggestion when a known key is close enough. The files using that configuration are skipped and the run exits with code 2. The error is reported for each skipped file and names the configuration file, while an invalid --config file is reported once:

doc/references.bib: error: /project/.bibclean.toml: invalid TOML: ...
error: /project/custom.toml: 'indent' in the top-level table must be ...

Options🔗

[tool.bibclean]
# formatting
indent = 2                   # a positive integer, or "tab"
align-values = false
trailing-comma = false
sort-entries = true
sort-fields = true           # true | false | ["author", "title", "year"]
month = "abbreviation"       # "abbreviation" | "name" | "number"

# linting
ignore = []                  # rule names disabled everywhere
exclude = []                 # cite keys exempt from the rules
exclude-types = []           # entry types exempt from the rules

Key

Type and default

Meaning

indent

integer or "tab", 2

Indentation of the field lines of an entry.

align-values

boolean, false

Pad the field names so that the = signs align inside an entry.

trailing-comma

boolean, false

Emit a comma after the last field of an entry.

sort-entries

boolean, true

Sort the entries by cite key, case-insensitively and stably, the entries named by a crossref field last, as BibTeX requires.

sort-fields

boolean or array of strings, true

true sorts the fields alphabetically, false preserves their order, an array places those names first, in that order, and sorts the rest alphabetically.

month

string, "abbreviation"

Target form of the month field: the macro feb, the name {February} or the number {2}. Ignore month-format to leave the field as written.

ignore

array of strings, []

Names of the rules that never run. See Rules.

exclude

array of strings, []

Cite keys exempt from every rule, compared exactly as written. Excluded entries are still formatted, and still count as the first occurrence for duplicate-key and duplicate-doi.

exclude-types

array of strings, []

Entry types exempt from every rule, compared in lower case. Excluded entries are still formatted.

Per entry type🔗

Each entry type has a table listing the fields it requires and the fields it keeps.

[tool.bibclean.article]
required = ["author", "journal", "title", "year"]
keep = ["doi", "month", "number", "pages", "url", "volume"]

required drives required-field. A name written with a bar, such as "author|editor", is satisfied when at least one of the alternatives is present, and is reported as written when none is.

keep drives strip-field. The effective list always contains the required names on top of the names listed, doi and url are never stripped, so a citation keeps its link, and crossref is never stripped, so an entry keeps the fields it inherits. An entry referenced by a crossref is not stripped either, since its fields are inherited.

The shipped tables below are the base. A user table overrides required and keep independently: a key left out keeps its default, and the default keep of a shipped type includes its shipped required names, so that dropping a name from required does not strip that field. A table for a type that has no shipped table must declare required, an empty list being enough, so that a misspelled type name such as [tool.bibclean.inproceeding] is reported instead of silently defining a new type. Such a type without keep is never stripped. Type names and field names are compared in lower case.
